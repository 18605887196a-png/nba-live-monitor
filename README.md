# NBA 滚球监控

一句话：**盯 NBA 滚球盘口，只推高胜率、真能成交的机会；只监控和分析，下单永远人手。**

2026-10-21 揭幕战（76人 @ 尼克斯、雷霆 @ 马刺）实盘跑通后封装。完整规则见 [SKILL.md](SKILL.md)。

最新：经验库（`experience/`）记录每条推送与用户实盘，终场自动对账出胜率与概率校准统计；快检工具 `scripts/fast_check.py` 约 3 秒扫完全场三盘与倒挂梯子。规则以 SKILL.md 为准（2026-10-24 定版）。

## 数据源

- ESPN scoreboard / summary 接口：实时比分、时钟、节次、球员 box score
- Polymarket gamma API：盘口 bestBid / bestAsk（只认真实买卖盘，不用会滞后的最近成交价）
- 下单在 Gate App 的 Polymarket 板块：与 Polymarket 同一订单簿、价格同源；Gate 另收单边 0.8% 手续费，算账用费后口径

## 胜率模型

WP = Φ((lead + M·t/48) / (13·√(t/48)))

- lead = 该队当前分差，M = 该队赛前预期全场分差（由让分主线读出），t = 剩余分钟
- 模型误差约 ±4 个百分点，t < 0.5 分钟停用

## 现行制度（2026-10-24 定版，取代 10-21 双轨制）

- 每天所有比赛都监控，只看胜负、让分、总分三盘，球员盘暂停
- 达标推送：概率 ≥90% 且局面稳就立刻推，不限节次；97¢ 以上定局价也推
- 捡漏第一优先：梯子倒挂（更容易中的线反而更便宜，差价 ≥1¢、两边真实报价、易中线概率 ≥85%）；受让线（对手负分盘的 No 边，严格占优于胜负盘）同样处理
- 排序：捡漏 > 胜负/总分 > 让分垫底；时效第一，达标出现约 1 分钟内就发，不攒批不等固定点
- 每场三节结束播报、终场对账；报价一律"¢数 + 倍率"双写；播报前以发送时刻重拉数据复核

## 经验库（2026-10-24 建）

- `experience/pushes.jsonl`：每条推送（场次、盘口、线、推送价、模型概率、类型、是否送达、终场结果），含漏发与误报
- `experience/bets.jsonl`：用户实盘（以他本人记录为准：买入价、份数、毛投入、Gate 退款、到账、盈亏），金额不全的只记输赢、不估算、不进盈亏统计
- `scripts/experience.py`：`settle` 按 event 拉 ESPN 终场自动判定，`stats` 出胜率、按类型/盘口拆分、模型概率分段 vs 实际命中率、实盘盈亏
- 历史：2026-10-21 揭幕战至今的推送与用户实盘已全部回填（正式推送 66 胜 3 负，用户实盘 9 胜 0 负）

## 边界

- 只做监控和分析，订单由人手在 Gate App 完成
- 高胜率不等于赚钱：90% 胜率的盘赔付常被压到 10% 以内，扣掉手续费后期望约为零或负数，推荐前必须把费后账算清
- 比赛结束 Polymarket 先走 UMA 结算再正式关闭，Gate 随后入账，一般终场后 1–3 小时
